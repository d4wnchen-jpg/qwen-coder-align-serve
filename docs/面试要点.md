# 面试要点速记：数据 → 训练 → 评估

> 用途：面试前快速过一遍本项目的核心知识点（Q = 面试官可能的问法）。
> 范围：data / train / eval 三部分。serve（部署压测）部分在 W5 完成后追加。

## 0. 一句话项目叙事

> 用 Magicoder-OSS-Instruct 自筛 3000 条代码指令数据，QLoRA SFT 把 Qwen3-8B
> 对齐为代码助手，EvalPlus（plus 版）评测提升，全程防数据污染、可复现。

---

## 一、数据（data）

**Q: 用的什么训练数据？为什么选它？**
- Magicoder-OSS-Instruct-75K（UIUC ISE Lab 出品，MIT 许可，75K 条）
- OSS-Instruct 造数法：真实开源代码作种子 → LLM 反推题目 → 生成解答（题目真实、多样、可溯源）
- 语言分布：Python 50.9%，shell/TS/C++/Rust/PHP/Java/Swift/C# 各约 6%
- 字段：problem / solution / lang / seed

**Q: 数据怎么清洗的？（6 条规则 + 审计）**
- 空值过滤；长度过滤（instruction ≤2000，output 50~4000）
- EvalPlus 关键词粗筛（防污染）；md5 精确去重
- 代码围栏成对（防截断）；骨架解答过滤（pass/TODO 占位 ≥30% 丢弃）
- 实现题无代码过滤（instruction 要求 implement/write/create 但 output 无代码 → 丢弃）
- 产出 train 3000 / dev 200；每条规则的丢弃数落盘 `report.json` 的 filter_stats
- 独立审计脚本 `audit_quality.py`：7 类检查（围栏/骨架/拒答/截断/语言错配/无代码/重复）

**Q: 为什么训练集和评测集必须不同源？**
- 防 data contamination（背题）：同源评测 = 测记忆而非能力，分数失真
- 三层防线：①官方 decontaminated 版数据源 ②清洗时关键词粗筛 ③评测固定 plus 版
- dev（同源 200 条）管训练过程监控（loss 曲线、过拟合预警）；EvalPlus（异源）管最终能力

**Q: 数据质量怎么发现的？举一个真实案例**
- 审计发现"倒置样本"：题目里已含完整解答，输出只是文字复述（无代码）——
  这类样本会教模型"输出描述而非代码"，对 SFT 有害，已用规则过滤

## 二、训练（train）

**Q: 用什么框架？整体流程？**
- LLaMA-Factory（HuggingFace Trainer + PEFT 的上层封装）
- 流水线：读 yaml → 加载基座模型 → 套模板+tokenize 数据 → 训练 → 保存 adapter
- yaml = 配方单：一次实验一个文件，可复现、可进 git、改两个数字就是新实验

**Q: LoRA 是什么？为什么用它而不是全参微调？**
- 冻结基座，只训练低秩补丁矩阵 A/B（rank 控制补丁参数量）
- 8B 全参训练显存爆炸；LoRA adapter 仅几十 MB，4090 可训
- QLoRA = 4bit 量化底座 + LoRA，再省显存（W3 的兜底方案）
- LoRA 可推理时动态挂载 → 正是 W5 multi-LoRA 热切换的原理（训练产物直接复用）

**Q: 训练超参为什么这么设？**
- lora_rank 16/64 × epoch 2/3 做矩阵实验（对照变量，选出最优）
- lr 2e-4 + cosine 调度 + 10% warmup（稳定起步、后期收敛）
- batch 2×grad_accum 8 = 等效 16；cutoff_len 2048 平衡显存与覆盖
- val_size 5% 每 200 步验证一次（防过拟合仪表盘）；bf16 训练（4090 原生支持）

**Q: yaml 里的参数是怎么"生效"的？（配置系统原理）**
- yaml 键 → LLaMA-Factory 的 dataclass 字段（声明处）→ PEFT 的 LoraConfig（消费处）→ 真插入 A/B 矩阵
- 键未声明：程序报错退出（防拼写错误）；声明但无人消费：静默失效（最阴的坑）
- 验证参数是否生效：grep 源码第二处引用，或改极端值看行为是否变化

## 三、评估（eval）

**Q: EvalPlus 是什么？**
- UIUC ISE Lab 的开源代码评测框架（NeurIPS 2023）；与 Magicoder 同实验室
- 三件套：题目集（HumanEval+ 164 题 / MBPP+ ~400 题）、加强测试用例、评分器（pass@1）
- 项目里两个角色：出卷人（evalplus.data 取题）+ 阅卷人（evalplus.evaluate 评分）

**Q: 常说的"HumanEval+ 测试用例 80 倍"是什么？**
- 原版 HumanEval 平均 ~7.7 用例/题 → + 版自动扩充到平均 ~616 用例/题（约 80 倍）
- 扩充的全是边界输入（空列表/负数/极值），几乎不存在于任何训练语料
- 效果：背题模型的分数原形毕露（原版高分 → plus 版掉 10-20 分）

**Q: pass@1 是什么？为什么 temperature=0？**
- 每题生成 1 次，通过全部测试用例才算过，通过率 = pass@1（最严格口径）
- temperature=0 贪心解码：结果确定、可复现、与公开模型分数可比
- pass@k（每题生成 k 次取最优）更宽松，项目统一用 pass@1

**Q: 生成+评分的脚本逻辑？**
- load_prompts：从 evalplus 取题，统一成 {task_id, prompt, entry_point}
- main：逐题 POST /v1/chat/completions（OpenAI 兼容协议）→ 剥 markdown 壳 → 写
  {task_id, solution} jsonl → 喂 evalplus.evaluate 评分
- 注意：HumanEval+ 是"半截函数续写"式，与训练数据"完整题面→完整解答"形式不同
  ——训练按产品形态，评测按行业统一考卷，分数才有可比性

**Q: 为什么用 argparse？**
- 一个脚本多套跑法（temperature/num-shots/out 等旋钮），改命令行不改代码
- add_argument = 声明参数（名字/类型/默认值），parse_args = 读命令行装进 args

## 附：防污染三件套（可能被连环追问）

1. 数据源选官方 decontaminated 版（用 EvalPlus 工具做过与考题的去重）
2. 清洗管线加 POLLUTION_HINTS 关键词粗筛（双保险）
3. 评测固定 plus 版（80× 用例，背题无处遁形）
